# Chord

A Safari Web Extension for macOS that puts useful actions on global keyboard shortcuts.

| Shortcut | Action |
|---|---|
| **⇧⌘P** | Toggle Picture in Picture for the best video on the page |
| **⇧⌘C** | Copy the current tab's URL and show an "Address copied" toast |

Clicking Chord's toolbar button opens the companion app window (status, toast setting, shortcuts).

## Layout

- `extension/` — web extension sources: `manifest.json`, `background.js`, `content.js`. The Xcode project references these files in place.
- `xcode/Chord/` — Xcode project generated by `xcrun safari-web-extension-converter`:
  - `Chord/` — companion app: settings window and the toast overlay.
  - `Chord Extension/` — `SafariWebExtensionHandler.swift`, the native side of the extension.

## Requirements

- macOS 14+ (the toast uses Liquid Glass on macOS 26+, and a blur material on older versions)
- Xcode, and an Apple ID added under Xcode → Settings → Accounts

## Install

1. Open `xcode/Chord/Chord.xcodeproj`.
2. For **both** targets (`Chord` and `Chord Extension`), open Signing & Capabilities, tick *Automatically manage signing*, and set Team to your personal team. The project's current `DEVELOPMENT_TEAM` is the author's; replace it with yours.
3. If you fork this, change the bundle IDs (`com.raggesilver.Chord` and `com.raggesilver.Chord.Extension`) to your own. The extension's ID must be `<app id>.Extension`. Also update `extensionBundleIdentifier` in `ViewController.swift` and the identifiers at the top of `AppDelegate.swift` and `SafariWebExtensionHandler.swift`.
4. Select the `Chord` scheme and destination *My Mac*, then press ⌘R. The app window opens; you can close it.
5. In Safari, enable the Develop menu (Settings → Advanced), then choose **Develop → Allow Unsigned Extensions**. This is needed for local builds and resets each time Safari relaunches.
6. Safari Settings → Extensions → tick **Chord**, then set website access to **Allow** for All Websites. The content script needs it to reach the video on a page.

Rebuilding with a changed bundle ID makes Safari treat Chord as a new extension, so you'll need to enable it and grant access again.

## Remap shortcuts

Safari Settings → Extensions → Chord → shortcut fields (Safari 26+). The manifest's `suggested_key` values are only defaults.

## How it works

**Picture in Picture.** The background script receives the `commands` event and messages the content script in all frames. The content script picks the video: one already in PiP first (so the shortcut exits), then the largest *playing* visible video, then the largest visible one. It calls `requestPictureInPicture()` or exits via `exitPictureInPicture()`, falling back to the WebKit-prefixed `webkitSetPresentationMode`.

**User gesture.** A command-triggered call can be rejected with `NotAllowedError`. Chord has two fallbacks:
1. The content script also listens for a trusted ⌘⇧P `keydown` in the page, which counts as a genuine gesture.
2. If the command call is rejected, the toolbar badge shows `↵` and the next click or keypress in the page completes PiP.

The tradeoff: the keydown route only works if Safari lets the keystroke reach the page, and the retry costs one extra click.

**Copy URL.** The background script sends the URL with `runtime.sendNativeMessage` to `SafariWebExtensionHandler`, which writes it to `NSPasteboard`. This avoids the clipboard permission and focus problems of writing from a script. The handler then asks the companion app to show a toast (launching it in the background if needed) and waits briefly for the app to confirm. If the toast was shown, no badge appears; otherwise the toolbar badge shows `✓` as a fallback.

**Toast.** A borderless, non-activating panel in the companion app, centered horizontally with its bottom edge 10% up from the bottom of the screen, using `NSGlassEffectView` (regular style) on macOS 26+. The "Show toast" checkbox in the app window controls it. The setting lives only in the app, so no app-group entitlement is needed. Closing the app window keeps it running hidden (no Dock icon) so it can host toasts; ⌘Q quits it, and the next copy relaunches it.

**Permissions.** `activeTab`, `nativeMessaging`, plus the `<all_urls>` content script match.

Toolbar badge symbols:

| Badge | Meaning |
|---|---|
| ✓ | URL copied (only when the toast is off or unavailable) |
| – | No usable video on the page |
| ↵ | PiP needs a click or keypress to finish |
| ! | Error |
| × | No content script on this page |

## Known limitations

- Pages with no `<video>`, videos with `disablePictureInPicture`, DRM or custom players that hide the element, and videos in cross-origin iframes where the content script isn't granted show the `–` badge.
- Restricted pages (Start Page, `safari://` URLs, App Store pages, PDFs) have no content script, so PiP doesn't work there. Copy URL still works if the tab URL is readable.
- **Shortcut conflicts.** Safari already uses ⇧⌘P (Page Setup…) and ⇧⌘C (element selection when Web Inspector is open) in some versions. If a built-in shortcut wins, the command won't fire; remap Chord's shortcut in Settings → Extensions.
- Extension shortcuts only fire while Safari is frontmost and the extension is allowed on the site.
- The toast's transparency can't be tuned: `NSGlassEffectView` only offers `.regular` and `.clear` styles, and the system's Liquid Glass transparency setting has no public API.
- The toast needs the companion app to launch from the extension. If macOS refuses, the `✓` badge appears instead.
- Not verified: behavior on Vimeo, and how Safari picks the reply when several iframes answer the PiP message.
